# 错误排查

## 先区分三个层次

HTTP状态、JSON中的业务code和本地进程退出码不是同一概念。CLI捕获的错误以JSON写到stderr；命令行语法错误由argparse输出普通帮助文本。

| 退出码 | 含义 |
|---|---|
| 0 | 客户端接受成功响应，仍需检查业务数据 |
| 1 | 鉴权、参数、网络、响应、文件等运行错误 |
| 2 | 缺少命令、未知选项、无法解析参数类型等命令语法错误 |

## HTTP错误

| 状态 | 当前CLI提示所表达的可能原因 | 处理 |
|---|---|---|
| 401 | Key缺失、无效或过期 | 检查执行进程的环境变量；联系服务方确认有效期 |
| 403 | 停用、权限不足或IP限制 | 核对接口、字段、区域及IP授权 |
| 404 | 接口未上线或无数据 | 先核对基础路径与接口；不能直接认定无气象数据 |
| 429 | 超过限流 | 确认频率或额度限制及恢复时间；不要循环重试 |
| 3xx | 不跟随重定向 | 向服务方获取无需重定向的正式地址 |
| 其他 | 通用请求失败 | 提供请求时间、接口、状态给服务方定位 |

客户端在HTTP错误时不解析响应体，因此不会输出其中可能存在的业务code或request_id。

例如HTTP401时CLI输出：

```json
{"error": "HTTP 401: Key 缺失、无效或过期"}
```

## 业务码

下表来自原接口文档，尚未生产联调。不要据此假定其HTTP映射。

| code | 来源含义 | 处理 |
|---|---|---|
| 4001 | 坐标错误 | 核对经纬度顺序、范围、坐标授权 |
| 4002 | 变量错误 | 核对拼写、大小写、接口支持及字段权限 |
| 4003 | 日期错误 | 使用有效YYYY-MM-DD，核对起止顺序 |
| 4004 | 历史范围错误 | 确认可查范围并缩短区间 |
| 4010 / 4011 / 4012 | 缺Token / 无效 / 过期 | 检查环境变量或续期 |
| 4030 / 4031 / 4032 | 停用 / IP / 接口权限 | 联系服务方核验授权 |
| 4040 | 无数据 | 确认日期、坐标和字段覆盖，不自动补0 |
| 4290 | 限流 | 确认恢复规则和额度 |
| 5000 / 5020 / 5030 | 内部错误 / 上游 / 不可用 | 记录时间与请求信息，联系支持 |

当HTTP请求成功但JSON业务码为4012时，CLI输出：

```json
{"error": "业务错误码 4012；请核对授权、参数和数据可用性"}
```

该输出是客户端生成的摘要，不是原始API返回。业务失败时也不保留服务端message/request_id。

## 常见本地问题

- 缺少Key：.env不会自动加载；变量需进入实际运行Python的环境。
- 网络或TLS失败：检查正式地址、DNS、代理、证书和网络；不要关闭TLS验证。
- 非有效JSON：可能收到网关或网页内容，核对路径和服务状态。
- 成功响应缺少data：与当前客户端合约不匹配，联系服务方。
- 输出文件已存在：换文件名；父目录不存在时先建目录。
- 响应超过64MiB：缩短日期或减少字段。
- 16天预测被拒绝：当前客户端仅接受1—15天，不能通过文档承诺扩大范围。

## 向支持提供什么

提供发生时间和时区、接口、脱敏参数、HTTP或业务错误文本、客户端提交版本。若原始HTTP响应确实含request_id，可一并提供；CLI失败摘要通常没有此字段。

不要提供Key、Authorization头或包含凭据的完整日志；公开反馈中还应隐藏敏感场站坐标。示例错误不代表已实际触发过线上接口。
